# Магазин или Двор — заметки к архиву

## Что НЕ менялось
Файлы Kaspi, Ozon, Wildberries (`src/integrations/*`) и список товаров My Market
(`src/routes/products.routes.ts`, вкладка «Товары» в админке) в этом изменении
**не трогал**. Заказы, курьер, накладная, код выдачи (`shop.routes.ts`,
`shopAdmin.routes.ts`, `waybill.service.ts`), Excel и юнит-экономика — тоже
без изменений. Ни одна существующая таблица и ни одна существующая модель
Prisma не менялись.

## Что добавлено (всё новое, отдельное)
- Модели Prisma: YardInvite, YardApplication, YardShop, YardItem, YardOrder,
  YardOrderItem, YardMessage. Внешние ключи ссылаются только друг на друга.
- Миграция `prisma/migrations/20260209000000_yard` — только CREATE TABLE/INDEX.
- Бэкенд: `src/services/yard.service.ts`, `src/routes/yard.routes.ts`
  (`/api/shop/yard/...`, x-app-key), `src/routes/yardAdmin.routes.ts`
  (`/api/yard-admin/...`), подключены двумя строками в `src/expressApp.ts`.
- Админка: отдельная страница `page-yard` и самая последняя красная кнопка
  сайдбара «Магазин или Двор» (не вложена во вкладки My Market).
  Вкладки внутри: Вакансия, Заявки, Магазины, Полки, Заказы.

## Поток
Вакансия (админ вписывает телефон/имя/фамилию/ИИН) → в приложении на этот номер
появляется заявка с заполненными данными → «Одобрить»/«Отказать» → при одобрении
создаётся YardShop и открывается кабинет с полкой. До одобрения товары грузить
нельзя (POST /yard/mine/items → 404).

## Что не удалось проверить в среде сборки
`prisma generate` и `prisma migrate deploy` здесь запустить нельзя (нет доступа к
binaries.prisma.sh). Миграции проверены на реальном PostgreSQL 16 по порядку
(все 38, включая новую), приложение — на подставной БД. Перед продом прогоните
`npx prisma generate` и `npx prisma migrate deploy` на staging.

## Категория товара полки (YardItem.category)
Новая миграция `20260210000000_yard_item_category` — один `ALTER TABLE "YardItem" ADD COLUMN "category" TEXT`
(nullable, у старых товаров NULL). Прошлая миграция двора не менялась.
`POST /api/shop/yard/mine/items` принимает `category` строкой (до 100 символов, пробелы по краям
обрезаются, списка категорий в коде нет). Не передали при правке — прежняя категория остаётся;
пустая строка или null — сбрасывает. `GET /yard/shop/:id` и `GET /yard/mine` отдают `category` у каждого
товара (у товаров без категории — null). Файлы Kaspi, Ozon, WB и список товаров My Market не менялись.

## Чат магазина без заказа (YardShopMessage)
Новая таблица `YardShopMessage` (миграция `20260211000000_yard_shop_messages`, идемпотентная: `IF NOT EXISTS`,
внешний ключ в защитном блоке). Существующий чат заказа (`YardMessage`), заказы и полки не менялись.
- `POST /api/shop/yard/shops/:id/messages` — тело `{shopId, buyerPhone, text | imageUrl}`; `shopId` обязан совпадать
  с адресом. Пишет клиент (по умолчанию отправитель = `buyerPhone`) или продавец — тогда добавляется `phone` (его телефон),
  а в `buyerPhone` — клиент, которому он отвечает.
- `GET /api/shop/yard/shops/:id/messages?phone=<кто читает>[&buyerPhone=<ветка>]` — клиент видит только свою ветку;
  продавец — входящие своего магазина (все ветки или одну).
- Ветка = (магазин, телефон клиента). Чужая ветка и чужой магазин — 403. Телефон магазина в ответах не отдаётся.
- Продавец отвечает только в ветку, где клиент уже написал первым. Клиенты пишут и читают только в магазин с действующей
  подпиской; владелец читает и отвечает всегда.

## Архив / удаление / поиск в разделе «Магазин или Двор» (вкладки Магазины, Полки, Заказы, Архив)
Миграция `20260212000000_yard_archive` (идемпотентная): колонка `archived BOOLEAN NOT NULL DEFAULT false`
у `YardShop`, `YardItem`, `YardOrder`.
- Вкладки «Магазины», «Полки», «Заказы»: сверху поиск по названию магазина, в каждой строке галочка, «отметить все»,
  кнопки «В архив» и «Удалить». Действие применяется только к отмеченным; без галочек кнопки выключены.
  Строки, скрытые поиском, из отмеченных выпадают. Пустой поиск = весь живой список, архив скрыт.
- Строка в «Полках» — полка магазина (все её товары разом); у пустой полки галочка выключена.
- «Архив» — отдельная вкладка справа, внутри подвкладки Магазины / Полки / Заказы; поиск, «отметить все»,
  «Вернуть» и «Удалить» работают и там.
- «Удалить» спрашивает «Удалить N?» и стирает записи на сервере. Магазин удаляется каскадом (заказы, позиции, переписка,
  чат магазина, товары). Остаток при удалении заказа на полку не возвращается.
- Магазин можно открыть (клик по названию), поправить название и сохранить.
- Эндпоинты `/api/yard-admin/`: `GET shops|items|orders` (+`?archived=true`), `POST shops|items|orders/archive`,
  `POST shops|items|orders/delete`, `POST shops/:id/rename`. Для «Полок» в теле `shopIds` (+`archived`).
- Архивный магазин и архивные товары покупателям не видны и не продаются. Архив не влияет на оборот двора.
- Оплата и закрытие заказа больше не падают, если товар заказа уже удалён с полки.
- Вкладки «Вакансия» и «Заявки», Kaspi, Ozon, WB, My Market и курьер не менялись.

## Вкладка «Заявки»: три раздела
«Новые» (pending), «Одобренные» (approved), «Отклонённые» (rejected). Заявка живёт ровно в одном разделе, общего списка нет.
«Одобрить» переводит новую заявку в «Одобренные» (и, как раньше, создаёт магазин), «Отклонить» — в «Отклонённые».
В каждом разделе: поиск по имени (имя, фамилия, «имя фамилия») и названию магазина — пустой поиск показывает только этот раздел;
галочка в каждой строке, «отметить все», «Удалить» пачкой с вопросом «Удалить N?». Строки, скрытые поиском, из отмеченных выпадают.
Новый эндпоинт `POST /api/yard-admin/applications/delete` (`{ids}`, стирает записи на сервере). Удаляется только сама заявка:
магазин, созданный при одобрении, и вакансия остаются. Данные те же — `GET /api/yard-admin/applications`.
Вкладка «Вакансия», Kaspi, Ozon, WB, My Market и курьер не менялись.

## Если на проде всё ещё старая версия
Сборка на Vercel — `npm run build && npx prisma migrate deploy` (см. `vercel.json`). Если этот шаг падает, Vercel не
публикует новую версию и отдаёт последнюю успешную. Проверка и лечение:
1. Vercel → Deployments → последний деплой → Build Logs: ищите `P3009` или ошибку миграции.
2. Если Prisma пометила `20260209000000_yard` упавшей — `npx prisma migrate resolve --rolled-back 20260209000000_yard`
   (с `DATABASE_URL`/`DIRECT_URL` прода), затем `npx prisma migrate deploy` и новый деплой.
3. Что проверить на проде после деплоя: `curl -s https://unit-v4.vercel.app/ | grep -c 'data-yardapps'` → должно быть 3.
   Если вместе со «Заявками» нет и «Архива» справа, и полок по магазинам — деплой не обновился целиком.
