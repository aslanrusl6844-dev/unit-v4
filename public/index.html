Каталог товаров

Kaspi: у Kaspi нет API-метода «отдай список всех моих товаров» (только методы добавления новых) — поэтому каталог собирается из реальных заказов при синхронизации. Из этого следуют два честных ограничения, которые нельзя обойти без такого метода у Kaspi: 1) статус «снят с продажи» Kaspi нам не отдаёт — переключатель «Активен» управляется только вручную (или через историю заказов), это не живая синхронизация с кабинетом; 2) товар, по которому ещё не было ни одной продажи (например, только что выложенный водонагреватель), физически не может появиться в каталоге сам — добавь его вручную или через массовую загрузку Excel/CSV ниже, тогда он сразу попадёт в «Активные» с себестоимостью и (для Kaspi) сразу посчитанной комиссией по категории.
Ozon: каталог подтягивается напрямую из «списка товаров» через API — попадают только товары со статусом видимости VISIBLE («сейчас видны покупателям»), снятые <<<<<<< HEAD с продажи в каталог не попадают. Вместе с каталогом подтягивается и тарифная сетка расходов (та же, что в кабинете Ozon → Цены и акции → Управление ценами) — комиссия и логистика заполняются автоматически, без единой продажи. Это предварительная оценка по тарифу, не факт по уже состоявшейся продаже (факт считается отдельно, после реальных продаж).

Прогноз показывается по выбранной наверху площадке (кнопки Kaspi/Ozon/WB) — своя цена, комиссия и логистика для каждой, считается по текущей цене прямо сейчас, даже без единой продажи на этой площадке. Ниши

Проверка товара/ниши Kaspi по ссылке или артикулу — MVP, только Kaspi.

Честно про точность: у официального Kaspi API нет метода, отдающего продажи или выручку ЧУЖОГО товара — таких данных нет вообще ни у кого, кроме самого продавца в его кабинете. Всё ниже (кроме случая, когда артикул уже есть в твоём каталоге) — оценка по публичной странице товара: то же самое, что видит любой покупатель. Продажи и выручка — особенно грубая оценка по числу отзывов (Kaspi не публикует ни сами продажи, ни даты отзывов) — ориентируйся на неё как на прикидку «есть спрос / нет спроса», а не как на точную цифру.

Настройки

Подключение к Kaspi-магазину, статус площадок и служебные ссылки.

Магазин Kaspi

Магазин ещё не добавлен.

Токен создаётся в кабинете Kaspi: Магазин на Kaspi.kz → Настройки → API. После сохранения он используется для всех запросов к Kaspi Seller API вместо переменной окружения.

Магазин Ozon

Магазин ещё не добавлен.

Client-Id и Api-Key создаются в кабинете продавца Ozon: Настройки → Seller API. Client-Id — это числовой ID (например, 123456), а не email и не название магазина. После сохранения они используются для всех запросов к Ozon Seller API вместо переменных окружения.

Магазин Wildberries

Магазин ещё не добавлен.

Токен создаётся в личном кабинете продавца Wildberries: Настройки → Доступ к API → Создать новый токен. Один и тот же токен используется и для заказов (категория доступа «Статистика»), и для каталога товаров (категория «Контент») — при создании токена отметь обе категории, иначе часть функций (например, «Каталог WB» на странице «Товары») будет недоступна. После сохранения токен используется для всех запросов к Wildberries API вместо переменной окружения.

Налог ИП

Налог считается от выручки (не от прибыли и не от суммы после комиссии) — так, как устроен упрощённый режим для ИП. По умолчанию 4%. Применяется сразу везде: «Финансы», «Обзор» и таблица «Товары».
